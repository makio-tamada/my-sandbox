# 検証レポートの書き方

レポートは**半年後の自分が読み返す**ためのもの。`templates/REPORT.md` を雛形にして
`reports/NNNN-slug.md` に書く。slug は `experiments/NNNN-slug/` と完全一致させる。

## 原則

1. **結論を冒頭 1 行で先出しする。** 「何が分かったか」を最初に書く。経緯から書き始めない
2. **実測値と推測を分ける。** 実行して得た数値だけを「結果」に書き、解釈は「考察」に書く
3. **確かめていないことは「未検証」と明記する。** 空欄にして曖昧にしない
4. **再現手順は他人が辿れる粒度で書く。** `experiments/NNNN-slug/` で叩いたコマンドをそのまま載せる
5. **失敗も書く。** 動かなかった、期待と違った、という結果にも価値がある

## 構成

```text
# NNNN: <テーマ>

**結論**: （1 行）

| Issue | PR | 実施日 | 種別 | 状態 |

## 何を確かめたかったか   ← 動機と仮説
## 前提・計測環境         ← マシン、Python とライブラリのバージョン、データ規模
## 手順（再現方法）       ← コマンドをそのまま
## 結果                   ← 実測値、表、図
## 考察                   ← 結果の解釈。実測値と混ぜない
## 未検証・残課題
## 参考リンク
```

## 図表

`reports/assets/NNNN-slug/` に置き、レポートから相対パスで参照する。
このディレクトリは `.gitignore` の対象外で、コミットして残す。

## 索引の更新

レポートを書いたら `reports/README.md` の表に行を追加する。列は
`番号 | テーマ | 種別 | 状態 | 結論 | Issue | 日付`。状態は 🔬 進行中 / ✅ 完了 / ❌ 断念。
**結論列は一覧で読める 1 行**にする。ここを読むだけで過去の検証を思い出せる状態を保つ。
