# 計測の作法

雑な計測は誤った結論を生み、レポートに残ると後から害になる。以下を守る。

## 計測する前に

1. **何を比較するのかを 1 行で書く。** 比較対象と、揃える条件（データ、マシン、並列度）を明確にする
2. **公平な条件にする。** 片方だけキャッシュが効いている、片方だけ並列、片方だけ型変換込み、といった
   非対称がないか確認する。避けられない差は結果に明記する

## 計測するとき

1. **ウォームアップを 1 回以上入れる。** 初回は import、JIT、ディスクキャッシュの影響を受ける
2. **複数回試行して中央値を取る。** 最低 3 回、できれば 5 回以上。平均より中央値（外れ値に強い）
3. **ばらつきを記録する。** 最小・最大、または標準偏差を残す。1 回きりの計測を結論にしない
4. **計測対象だけを測る。** データ読み込みを比較したいのでなければ、時間計測の外に出す
5. **`time.perf_counter()` を使う。** `time.time()` は使わない

## 記録すること

レポートの「前提・計測環境」に必ず残す。これがないと後から再現も比較もできない。

- マシン（CPU、メモリ、macOS のバージョン）
- Python のバージョンと、比較対象ライブラリのバージョン（`uv tree` や `uv pip list` の出力）
- データの規模（行数、列数、ファイルサイズ）
- 試行回数

## 数値の書き方

- 有効数字は 3 桁程度に揃える。`1.23 秒` であって `1.2345678 秒` ではない
- 「N 倍速い」と書くときは、比較の基準（分母）を明示する
- 差が試行のばらつきの範囲内なら、**差がなかったと書く**。速いと書かない

## やってはいけないこと

- 実行していない数値を書く、または過去の記憶から数値を書く
- 1 回の計測結果を「〜倍速い」と一般化する
- 計測環境を書かずに数値だけ残す
