# LLM 検証の作法

## 書き始める前に

**`claude-api` スキルを先に読む。** モデル ID・料金・パラメータを記憶で書かない。
現行のモデル ID は `claude-opus-5` / `claude-sonnet-5` / `claude-haiku-4-5-20251001` / `claude-fable-5-1`。

雛形は `templates/llm-anthropic/` を使う。

## API キー

- `.env` の `ANTHROPIC_API_KEY` を環境変数として読む（`os.environ["ANTHROPIC_API_KEY"]`）
- **キーの値をコード・出力・レポート・コミットに書かない。** `.env` は `.gitignore` 済み
- キーが未設定なら、エラーメッセージで `.env.example` を案内して終了する

## 検証コードの作り方

1. **モデル ID とパラメータは 1 箇所の定数にまとめる。** 比較検証で差し替えやすくする
2. **リクエストとレスポンスを保存する。** `experiments/NNNN-slug/runs/` に JSON で残すと後から検証できる
3. **`usage`（入力・出力トークン数）を必ず出力する。** コスト概算とコンテキスト設計の根拠になる
4. **失敗ケースを握りつぶさない。** レート制限、リフューザル、途中で切れた出力はそのまま記録する

## 出力の揺らぎを踏まえる

LLM の出力は決定的ではない。**1 回の出力を根拠に結論を書かない。**

- 同じプロンプトを最低 3 回試し、揺らぎの幅を記録する
- 揺らぎを抑えたいなら `temperature` を下げ、その値をレポートに書く
- 「このプロンプトだとこうなる」と書くときは、試行回数と再現率（3 回中 3 回など）を添える

## レポートに残すこと

- モデル ID、`max_tokens`、`temperature`、system プロンプトの有無
- 試行回数と、出力が揺らいだかどうか
- 入力・出力トークン数と、公表単価から計算した概算コスト（単価は `claude-api` スキルで確認する）
- プロンプト全文（長ければ `experiments/NNNN-slug/` のファイルへリンク）
